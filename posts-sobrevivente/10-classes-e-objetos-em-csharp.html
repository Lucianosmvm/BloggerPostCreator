Resumo rápido

  • Classe é o molde: descreve os dados e as ações de algo, como um personagem.
  • Objeto é uma cópia de verdade criada a partir do molde, com new.
  • Campos guardam os dados do objeto; métodos são as ações dele.
  • O construtor roda quando o objeto nasce e define os valores iniciais.
  • Cada objeto tem os seus próprios valores: ferir um não fere o outro.

Até agora, o personagem do jogo era um monte de variáveis soltas: nome, vida, balas. Funciona para um personagem. Mas e quando aparecem dois jogadores, cinco inimigos e um cachorro? Você vai criar vidaDoInimigo1, vidaDoInimigo2... e se perder rapidinho.

As classes resolvem isso: você descreve uma vez o que é um personagem e cria quantos quiser a partir dessa descrição. É a base da Programação Orientada a Objetos (POO).

Classe é o molde, objeto é o personagem

Pense na ficha de personagem em branco de um RPG. Ela diz que todo personagem tem nome, vida e balas, mas ainda não é ninguém. Essa ficha em branco é a classe. Quando você preenche uma ficha para o Leon, ela vira um objeto.

ConceitoNo jogoNo código
Classea ficha em branco de personagemclass Personagem { ... }
Objetoa ficha preenchida do Leonnew Personagem()
Campoum dado da ficha: vida, balaspublic int Vida;
Métodouma ação: atacar, curarpublic void Curar() { ... }

Criando a primeira classe

C#

Personagem leon = new Personagem();
leon.Nome = "Leon";
leon.Vida = 100;
leon.Balas = 12;

leon.MostrarStatus();

class Personagem
{
    public string Nome = "";
    public int Vida;
    public int Balas;

    public void MostrarStatus()
    {
        Console.WriteLine($"{Nome} | Vida: {Vida} | Balas: {Balas}");
    }
}

Saída esperada

Leon | Vida: 100 | Balas: 12

Passo a passo:

  • class Personagem { ... } cria o molde. Dentro ficam os campos (Nome, Vida, Balas) e os métodos (MostrarStatus).
  • new Personagem() cria um objeto de verdade na memória.
  • O ponto acessa o que está dentro do objeto: leon.Vida = 100 muda a vida desse personagem, e leon.MostrarStatus() chama a ação dele.
  • public deixa o campo ser usado de fora da classe. Vamos falar dele com calma no post de modificadores de acesso.

Vários objetos, cada um com seus valores

A mágica aparece quando você cria mais de um objeto. Cada um guarda os próprios valores:

C#

Personagem leon = new Personagem();
leon.Nome = "Leon";
leon.Vida = 100;

Personagem zumbi = new Personagem();
zumbi.Nome = "Zumbi";
zumbi.Vida = 60;

zumbi.ReceberDano(25);
zumbi.ReceberDano(40);
leon.ReceberDano(10);

class Personagem
{
    public string Nome = "";
    public int Vida;

    public void ReceberDano(int dano)
    {
        Vida -= dano;
        if (Vida <= 0)
        {
            Vida = 0;
            Console.WriteLine($"{Nome} caiu!");
        }
        else
        {
            Console.WriteLine($"{Nome} agora tem {Vida} de vida.");
        }
    }
}

Saída esperada

Zumbi agora tem 35 de vida.
Zumbi caiu!
Leon agora tem 90 de vida.

O método ReceberDano foi escrito uma vez só, mas age em cima do objeto que o chamou: zumbi.ReceberDano(25) mexe na vida do zumbi, nunca na do Leon.

Construtor: o personagem já nasce pronto

Criar o objeto e depois preencher campo por campo é repetitivo, e dá para esquecer algum. O construtor é um método especial que roda no momento do new. Ele tem o mesmo nome da classe e não tem tipo de retorno:

C#

Personagem leon = new Personagem("Leon", 100);
Personagem jill = new Personagem("Jill", 80);

leon.MostrarStatus();
jill.MostrarStatus();

class Personagem
{
    public string Nome;
    public int Vida;
    public int Balas;

    public Personagem(string nome, int vida)
    {
        Nome = nome;
        Vida = vida;
        Balas = 6;   // todo personagem começa com 6 balas
    }

    public void MostrarStatus()
    {
        Console.WriteLine($"{Nome} | Vida: {Vida} | Balas: {Balas}");
    }
}

Saída esperada

Leon | Vida: 100 | Balas: 6
Jill | Vida: 80 | Balas: 6

Agora é impossível criar um personagem sem nome e sem vida: o new Personagem() vazio nem compila, porque o único construtor exige os dois valores.

A palavra this

É comum o parâmetro do construtor ter o mesmo nome do campo. Para diferenciar, use this, que significa "este objeto":

C#

Arma pistola = new Arma("Pistola", 15);
Console.WriteLine($"{pistola.nome} causa {pistola.dano} de dano.");

class Arma
{
    public string nome;
    public int dano;

    public Arma(string nome, int dano)
    {
        this.nome = nome;   // campo do objeto = parâmetro
        this.dano = dano;
    }
}

Saída esperada

Pistola causa 15 de dano.

Sem o this, nome = nome só copiaria o parâmetro para ele mesmo e o campo ficaria vazio. Por isso muita gente prefere nomes diferentes, como no exemplo anterior (Nome = nome).

Juntando tudo: um combate

C#

Personagem leon = new Personagem("Leon", 100, 15);
Personagem zumbi = new Personagem("Zumbi", 45, 10);

leon.Atacar(zumbi);
zumbi.Atacar(leon);
leon.Atacar(zumbi);
leon.Atacar(zumbi);

class Personagem
{
    public string Nome;
    public int Vida;
    public int Forca;

    public Personagem(string nome, int vida, int forca)
    {
        Nome = nome;
        Vida = vida;
        Forca = forca;
    }

    public bool EstaVivo() => Vida > 0;

    public void Atacar(Personagem alvo)
    {
        if (!EstaVivo() || !alvo.EstaVivo()) return;
        alvo.Vida = Math.Max(alvo.Vida - Forca, 0);
        Console.WriteLine($"{Nome} ataca {alvo.Nome}: {alvo.Nome} fica com {alvo.Vida}.");
    }
}

Saída esperada

Leon ataca Zumbi: Zumbi fica com 30.
Zumbi ataca Leon: Leon fica com 90.
Leon ataca Zumbi: Zumbi fica com 15.
Leon ataca Zumbi: Zumbi fica com 0.

Repare que um objeto pode receber outro objeto como parâmetro: Atacar(Personagem alvo). É assim que as peças do jogo conversam entre si.

Erros comuns

1. Usar o objeto sem criar com new. Personagem leon; só declara a variável. Sem new, não existe objeto, e acessar leon.Vida dá erro.

2. Confundir classe e objeto. Personagem.Vida = 100 não funciona: a vida é de cada personagem, não do molde. Use o objeto: leon.Vida = 100.

3. Construtor com tipo de retorno. public void Personagem(...) vira um método comum, não um construtor. Construtor não tem void nem outro tipo.

4. Esquecer o public. Sem ele, o campo fica private e não pode ser usado de fora da classe.

    Ver resposta

    Ver resposta

    public void Curar(int quantidade) { Vida = Math.Min(Vida + quantidade, 100); }

Conclusão

Com classes, o seu jogo deixa de ser uma pilha de variáveis e vira um mundo de objetos: personagens, armas e inimigos, cada um com seus dados e suas ações. Escreveu o molde uma vez, cria quantos quiser.

Mas do jeito que está, qualquer parte do código pode fazer leon.Vida = -500. Para proteger os dados do objeto existem as propriedades.
