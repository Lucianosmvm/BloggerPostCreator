Resumo rápido

  • Número mágico é um valor solto no código sem explicação, como if (vida > 37).
  • const é um valor fixo, conhecido ao compilar: números, textos e bool.
  • readonly é um campo que só pode ser definido na criação do objeto (na declaração ou no construtor).
  • static readonly é um valor único para a classe, calculado quando o programa roda.
  • enum dá nome a um conjunto fechado de opções, como as dificuldades do jogo.

No post de variáveis em C# você viu o básico do const. Aqui vamos mais fundo: quando usar const, quando usar readonly, o que muda com static e como o enum organiza opções fixas.

O problema dos números mágicos

C#

int vida = 30;
int ervas = 2;

if (vida < 35)
    Console.WriteLine("Use uma erva!");

vida = Math.Min(vida + ervas * 25, 100);
Console.WriteLine($"Vida: {vida}");

Saída esperada

Use uma erva!
Vida: 80

O que é 35? E 25? E se 100 aparecer em dez arquivos e a vida máxima mudar para 120? Esses valores soltos são os números mágicos: funcionam, mas ninguém sabe o que significam e mudar um deles é caça ao tesouro.

const: o valor fixo para sempre

C#

const int VidaMaxima = 100;
const int VidaCritica = 35;
const int CuraPorErva = 25;
const string NomeDoJogo = "Cidade Abandonada";

int vida = 30;
int ervas = 2;

Console.WriteLine($"== {NomeDoJogo} ==");
if (vida < VidaCritica)
    Console.WriteLine("Use uma erva!");

vida = Math.Min(vida + ervas * CuraPorErva, VidaMaxima);
Console.WriteLine($"Vida: {vida}");

Saída esperada

== Cidade Abandonada ==
Use uma erva!
Vida: 80

O resultado é igual, mas agora o código explica a regra. E a vida máxima muda em um lugar só.

O const tem limites: o valor precisa ser conhecido na hora de compilar, e só funciona com tipos simples, como números, bool, char e string. O compilador copia o valor para cada lugar onde a constante é usada.

C#

const DateTime Inicio = DateTime.Now;        // erro: só se sabe ao rodar
const int[] Andares = { 1, 2, 3 };           // erro: array não pode ser const

readonly: definido na criação, depois trancado

E quando o valor só é conhecido quando o objeto nasce? Cada personagem tem uma vida máxima diferente, escolhida na criação, que depois não deve mudar. É o caso do readonly:

C#

Personagem tanque = new Personagem("Brutus", 150);
Personagem batedor = new Personagem("Ada", 80);

tanque.Curar(500);
batedor.Curar(500);

class Personagem
{
    public readonly string Nome;
    public readonly int VidaMaxima;
    public int Vida;

    public Personagem(string nome, int vidaMaxima)
    {
        Nome = nome;
        VidaMaxima = vidaMaxima;   // só aqui (ou na declaração) pode atribuir
        Vida = vidaMaxima / 2;
    }

    public void Curar(int quantidade)
    {
        Vida = Math.Min(Vida + quantidade, VidaMaxima);
        // VidaMaxima = 999;   // erro: readonly fora do construtor
        Console.WriteLine($"{Nome}: {Vida}/{VidaMaxima}");
    }
}

Saída esperada

Brutus: 150/150
Ada: 80/80

Cada objeto tem o seu próprio valor de VidaMaxima, mas depois do construtor ninguém consegue mudá-lo, nem a própria classe.

static readonly: um valor para todos, calculado ao rodar

Quando o valor é o mesmo para todo mundo, mas não dá para ser const (porque é um array, um objeto ou depende de algo calculado), use static readonly:

C#

Console.WriteLine($"Itens iniciais: {string.Join(", ", Regras.KitInicial)}");
Console.WriteLine($"Servidor ligado em: {Regras.Inicio:yyyy}");

static class Regras
{
    public static readonly string[] KitInicial = { "faca", "lanterna", "erva" };
    public static readonly DateTime Inicio = new DateTime(2026, 10, 31);
}

Saída esperada

Itens iniciais: faca, lanterna, erva
Servidor ligado em: 2026

💡 readonly não congela o array

static readonly string[] KitInicial impede trocar o array inteiro (KitInicial = ...), mas ainda deixa mudar um item (KitInicial[0] = "pistola"). Para uma lista que ninguém altera, use IReadOnlyList<string> ou um ImmutableArray.

Regra prática: se o valor é uma verdade universal e simples (vida máxima, tamanho do pente), const. Se depende do objeto, readonly. Se é um objeto ou lista compartilhada, static readonly.

enum: um conjunto fechado de opções

Dificuldade do jogo com int vira confusão: 0 é fácil? 2 é difícil? E se alguém passar 7? O enum cria um tipo com opções nomeadas:

C#

Dificuldade escolhida = Dificuldade.Pesadelo;

Console.WriteLine($"Dificuldade: {escolhida}");
Console.WriteLine($"Zumbis por sala: {ZumbisPorSala(escolhida)}");

foreach (Dificuldade d in Enum.GetValues<Dificuldade>())
    Console.WriteLine($"  {(int)d} = {d}");

static int ZumbisPorSala(Dificuldade d) => d switch
{
    Dificuldade.Facil => 1,
    Dificuldade.Normal => 3,
    Dificuldade.Pesadelo => 6,
    _ => 3
};

enum Dificuldade
{
    Facil,
    Normal,
    Pesadelo
}

Saída esperada

Dificuldade: Pesadelo
Zumbis por sala: 6
  0 = Facil
  1 = Normal
  2 = Pesadelo

Por baixo, cada opção é um número (0, 1, 2...), mas no código você escreve Dificuldade.Pesadelo. O compilador não deixa passar um texto qualquer onde se espera uma Dificuldade, e o editor sugere as opções enquanto você digita.

Erros comuns

1. Tudo vira const. Valores que mudam por fase ou por personagem não são constantes. Use readonly ou uma configuração.

2. const público em biblioteca. Como o valor é copiado ao compilar, quem usa a sua DLL continua com o valor antigo até recompilar. Em bibliotecas, prefira static readonly para valores que podem mudar entre versões.

3. Enum convertido de qualquer número. (Dificuldade)7 compila e cria um valor que não existe na lista. Ao converter números vindos de fora, confira com Enum.IsDefined.

4. Nome que não explica. const int Cem = 100; não resolve nada. O nome deve dizer o significado: VidaMaxima.

DESAFIO

Tente resolver antes de abrir a resposta. Sobreviveu? Vá para o próximo.

  1. const int[] Saidas = { 1, 4 }; compila? Se não, como resolver?

    Ver resposta

    Não: array não pode ser const. Use static readonly int[] Saidas = { 1, 4 };.

  2. Cada arma tem um dano base escolhido na criação que nunca muda. const ou readonly?

    Ver resposta

    readonly, porque o valor muda de uma arma para outra e é definido no construtor.

  3. Crie um enum Clima com Sol, Chuva e Neblina e uma expressão switch que devolve a visibilidade em metros (100, 60 e 20).

    Ver resposta

    enum Clima { Sol, Chuva, Neblina } e int Visibilidade(Clima c) => c switch { Clima.Sol => 100, Clima.Chuva => 60, _ => 20 };

Conclusão

Trocar números mágicos por const, guardar o que nasce com o objeto em readonly e organizar opções com enum deixa o código do jogo mais fácil de ler e muito mais difícil de quebrar sem querer.
